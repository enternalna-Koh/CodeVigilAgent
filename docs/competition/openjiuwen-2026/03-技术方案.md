# 技术方案

## 1. 总体架构

CodeVigil Agent 采用 **「对话编排 + 专业规则 + 只读工具 + 显式生产力」** 分层：

```text
用户终端 (reviewagent / ra)
        │
        ▼
┌─────────────────── ConversationAgent ───────────────────┐
│  AI自动调换: light / infra / general                     │
│  会话: /new /back /sessions · Skills 挂载 · MCP 注册表   │
└──────────┬───────────────────────────────┬──────────────┘
           │                               │
           ▼                               ▼
   专业路由 specialist_context      调查循环 investigate
   operator | inference | opengauss   web / local / fetch / mcp_call(只读)
           │                               │
           ▼                               ▼
   .cursor/agents + skills          GitHub/GitCode API · ascend-doc MCP
           │
           ▼
   SmartReviewer / patch_fix · git_work (/commit /push /pr /ship)
```

对应 openJiuwen 概念映射（便于评委理解，**非声称已接入平台**）：

| openJiuwen 概念 | 本作品实现 |
|-----------------|------------|
| ReActAgent | `investigate` JSON 单步规划：Thought→Tool→Observe，最多 3 步 |
| WorkflowAgent | `/fix→/apply→/commit→/push→/pr` 与 `/ship` 确认流水线 |
| Skills | `.cursor/skills` + `/skill install` 官方包 |
| MCP | stdio JSON-RPC 客户端；内置 `ascend-doc` |
| Agent Studio | 暂以 CLI + Cursor Subagent 为开发面；可演进 WorkSwarm |

## 2. 核心能力模块

### 2.1 感知与取证

- 解析 GitHub / GitCode PR·Issue URL，拉取正文、评论、文件补丁；GitCode PR 附加 CI check-runs 摘要。
- 长文本粘贴作为本地审查对象；`/ci` 解析失败日志启发式模式。
- 社区批量采集：`collect --community opengauss|ascend-pytorch` → `data/raw`、`data/ci_runs`、`data/review_dialogs`。

### 2.2 规划与路由

- **AI 自动调换**：根据话轮与是否含 Infra 证据切换日常/正式车道。
- **场景检测**：路径与代码证据分流算子 / 推理 / openGauss；含糊则提问，不猜。
- **专业上下文预算**：16,000 字符 + 32 KiB UTF-8；超限标 incomplete，不截半条红线装完整。

### 2.3 工具调用（安全）

| 工具 | 用途 | 约束 |
|------|------|------|
| `web_search` | 官方文档线索 | `/network` 门控 |
| `local_search` | 本地社区案例 | 只读 |
| `fetch_pr_issue` | 单条 URL 取证 | 只读 |
| `mcp_call` | 昇腾文档等 | 自动调用须 `readOnlyHint=true` 且非 destructive |

本地写盘：`/apply` 前必须预览；Git 禁 force / amend；分支名校验防误删脏工作区。

### 2.4 生产力闭环

`/git` · `/commit` · `/push` · `/pr` · `/ship`（逐步确认）把「建议」落成「可合并改动」。

## 3. 技术栈与依赖

| 层 | 选型 |
|----|------|
| 运行时 | Node 启动器 + Python 3.7+ 核心 |
| 模型 | 多 Provider（DeepSeek / OpenAI 兼容 / Claude / GLM），支持 cc-switch 环境注入 |
| 知识 | 本地 JSON 案例库 + Skills Markdown + MCP 文档 |
| 测试 | unittest 209 项；npm test 复用同一套 |
| 许可 | MIT；第三方依赖单独声明 |

**不依赖**统一官方数据集（符合 FAQ Q19）；社区数据由公开 API 合规采集并注明来源。

## 4. 创新点

1. **领域垂直 Agent**：不是泛聊天，而是昇腾 / AI Infra 验收口径 + 开源社区工作流。
2. **自动调换 + 专业三条路由**：闲聊不扰、审查上强度；openGauss 证明范式可迁移。
3. **Skills × MCP 双轨扩展**：文件技能与官方文档 MCP 并存，安装不污染待审仓库。
4. **安全默认**：只读调查、补丁确认、token 平台隔离（GitCode 不用 GitHub token）。
5. **可复现工程**：离线审查、预算与来源写入报告、大规模回归守护边界。

## 5. 与第三方代码关系（开源合规预备）

- 主体编排、路由、Git/MCP/采集逻辑为本仓库实现。
- 可选安装的 Ascend 官方 skill 正文来自公开仓，安装到 `~/.reviewagent/skills/`，占比可控、可追溯。
- `ascend-doc-mcp` 为运行时拉取的官方包，不 vendoring 进参赛主体。
- 演示不提交真实 Token；提供 `.env` 占位说明即可。

## 6. DEMO 阶段演进（创意通过后）

2. 可选：在 WorkSwarm 注册「审查 / 采集 / 文档检索」工具节点，展示平台协同加分路径。
3. 补齐演示脚本、架构图导出、答辩 PPT。

## 一、智能体设计（演讲时务必说清）

### 1.1 一句话定位

不是「会聊天的大模型套壳」，而是一台带**工具、专业规则、安全确认链**的 Agent：  
能取证、会路由、可查文档，并且在用户确认后才真正改本地代码与 Git。

### 1.2 整体架构（口播可用）

```text
用户（自然语言 / 斜杠命令 / 桌面按钮）
        │
        ▼
┌──── ConversationAgent（编排脑）─────────────────────────┐
│  · AI 自动调换：闲聊 light / 通用 general / Infra work   │
│  · 多会话 /new /back · Skills 挂载 · MCP 注册表         │
│  · 自然语言生产力：出计划 → 用户「确认」→ 真实工具执行   │
└────┬──────────────────────────────┬─────────────────────┘
     │                              │
     ▼                              ▼
专业路由 specialist_context    只读调查 investigate
算子 | 推理 | openGauss         web / local / fetch_pr
→ agents + Skills               mcp_call(ascend-doc, 只读)
     │                              │
     └──────────┬───────────────────┘
                ▼
      SmartReviewer / 审查报告
                │
                ▼  （需用户确认）
      patch_fix 写盘 · git_work：commit / push / PR
      （禁 force / amend；GitCode 开 PR 给网页链接）
```

### 1.3 四层分工（对应 openJiuwen 概念，便于评委理解）

| 层 | 本作品实现 | 作用 |
|----|------------|------|
| 感知 | 解析 GitHub/GitCode URL、拉 PR/Issue/CI、本地粘贴、`@文件` | 拿到证据 |
| 规划 | AI 自动调换 + 场景路由 + 自然语言工作计划 | 决定「审 / 修 / 提交」 |
| 工具 | 只读：搜索、案例、MCP 文档；写：补丁、git（确认后） | 真正干活 |
| 记忆/扩展 | Skills、自定义命令、社区 `collect`、会话 `/save` | 可沉淀、可扩展 |

与 openJiuwen 概念映射（**说明用，不声称已接入平台**）：

| openJiuwen | CodeVigil |
|------------|-----------|
| ReActAgent | `investigate`：Thought→Tool→Observe，最多 3 步 |
| WorkflowAgent | `/fix→/apply→/commit→/push→/pr` 或自然语言「确认」整段执行 |
| Skills | `.cursor/skills` + `/skill install` |
| MCP | 内置 `ascend-doc`（进程信任确认 + 固定版本） |

### 1.4 两条干活路径（重点强调）

**路径 A — 审查（默认安全）**

1. 用户贴链接或点「审查当前改动」  
2. 自动调换到 Infra 车道，加载 Skills / 查 MCP  
3. 输出可证实问题与建议  
4. **此阶段不写盘、不 push**

**路径 B — 生产力（一次确认）**

1. 自然语言例如：`拉取 https://…/pulls/6 并按审查意见修改`  
2. Agent **只输出计划**，不假装「正在 clone」  
3. 用户回复 `确认` → 真实执行：clone/切分支 → 生成补丁并写盘  
4. 再说 `提交并开 PR…` → 再出计划 → `确认` → commit / push / 开 PR  
5. 全程 **禁止 force / amend**；可随时说 `取消`

备用显式命令（演示可提一句）：`/fix` → `/apply` → `/ship`

### 1.5 为什么这样设计

| 问题 | 设计选择 |
|------|----------|
| 通用助手只聊不做 | 工具闭环 + 专业路由 |
| 模型乱改仓库 | 默认只读；写操作必须确认 |
| 规则散落多仓 | Skills × MCP，按场景加载 |
| 假执行骗用户 | 副作用只能走真实函数（`work_clone` / `patch_fix` / `git_work`） |

## 二、完整口播稿（可直接念）

### 开场（约 20 秒）

> 大家好，我们是三三队。作品叫 CodeVigil Agent。  
> 它解决昇腾 / AI Infra 开发里三个痛点：验收规则散落、通用助手只会聊、自动改仓不安全。  
> 我们的目标：把大模型变成能取证、能审查、在确认后才提交的智能体。

### 设计（约 40 秒）

> 架构上分四层：感知、规划、工具、扩展。  
> 编排中枢是 ConversationAgent：闲聊保持轻量，贴上 GitCode 或 GitHub 链接就自动进入 Infra 审查车道，按算子、推理、openGauss 三条专业路由加载 Skills，并用昇腾文档 MCP 做只读取证。  
> 写代码和 Git 不走「嘴上答应」：要么斜杠命令 `/fix` `/apply` `/ship`，要么自然语言先出计划，你说「确认」后才真实 clone、写盘、commit、push。绝不 force、不 amend。

### 演示（约 80 秒，边做边说）

> 现在打开 CLI。先看版本和帮助。  
> 贴一条公开 PR 链接——注意自动调换到正式审查，输出带位置和建议的报告。  
> 再演示 `/skill list` 和 `/mcp`，说明专业技能与文档工具是分开挂载的。  
> 若时间够：说一句「拉取这个 PR 并修改…」，屏幕上只出现计划；说「确认」才开始执行——这就是我们说的生产力，而不是假进度条。

### 收尾（约 20 秒）

> 项目已开源 MIT，支持 CLI 和桌面版，仓库在 GitHub CodeVigilAgent。  
> 边界也说清楚：我们不替代真实 NPU 上板精度验证，也不虚构已经接入 openJiuwen WorkSwarm；平台封装是 DEMO 阶段可选演进。  
> 谢谢评委。

## 3. 落地路径（分阶段）

### 阶段 A：个人 / 实验室（已完成）

1. Node≥14（推荐≥22）+ Python 3.7+  
2. `npm i -g reviewagent` 或克隆仓库本地运行  
3. 配置自备大模型 API（DeepSeek / OpenAI 兼容 / Claude / GLM 等）  
4. 粘贴 GitCode/GitHub 链接或关键词即可审查

### 阶段 B：社区导师场景（部分完成）

1. 配置 `GITCODE_TOKEN`（仅 GitCode，与 GitHub Token 隔离）  
2. `collect --community opengauss|ascend-pytorch` 沉淀对话与 CI  
3. 用 Skills 复用审核口径，减少重复口头反馈

### 阶段 C：DEMO / 平台加分（创意晋级后，规划中）

1. 3 分钟视频：装 CLI → 贴 Issue → 报告 → `/fix` 预览（脱敏）  
2. 可选：将审查/采集/文档检索封装为 openJiuwen WorkSwarm 工具节点  
3. **不虚构**当前已接入 WorkSwarm；材料中区分「已有」与「规划」

## 4. 资源依赖与成本

| 资源 | 是否必需 | 说明 |
|------|----------|------|
| 大模型 API | 是 | 用户自备；支持多 Provider |
| GitCode Token | 否 | 仅采集/部分 GitCode 增强需要 |
| 昇腾 NPU 实机 | 否（创意/CLI 演示） | 上板精度验证属任务侧，Agent 不替代实测 |
| 公网 | 可选 | `/network` 门控；可偏本地 Skills |

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 模型幻觉改坏仓库 | 默认只读；写盘须预览确认 |
| Token 泄露 | 不提交 `.env`；演示脱敏；平台隔离 |
| 规则过时 | Skills/MCP 可更新；报告带来源 |
| 平台绑定争议 | 主体为开源 CLI；WorkSwarm 为可选演进 |
